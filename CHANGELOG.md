# Changelog

## [Unreleased]

### Added

- **`make add-method` — scaffold a method that lives elsewhere into the app.** `make add-method METHOD=github.com/Pipelex/methods/text_stats@v0.1.1` (or `METHOD=mt_…`) writes a `methods/<name>/method.json` manifest naming the method, its generated tree, a typed narrower, the Server Action trio, an action test, a form component, and a tab entry — then names the one line to replace once you know what the output should look like. It is the template's own "add a pipeline" checklist, executed: the method stays where it lives, and everything the demo tabs have by hand is written by the same projections. The gesture is **one-shot** — it refuses rather than overwriting, because the files it writes are yours from the moment they land, and `npm run codegen` is the refresh. Nothing is written until everything has been fetched, derived and checked, so every refusal leaves the tree untouched and `DRY_RUN=1` stops at that boundary and prints the plan. `PIPE=` picks the pipe when a package carries several, `NAME=` and `LABEL=` override the derived names. The reference is [`docs/add-method.md`](docs/add-method.md).

- **A plural output is read through `wireListOutput`, because the runtime renders a list output two ways.** The first scaffolded plural slice (a catalog method producing `CandidateMatch[]`) failed its very first run in Durable mode with `expected object, received array`: the scaffold had declared the `{ items: [ … ] }` envelope measured on the blocking `execute` response, and the durable `main_stuff.json` for a method-declared concept is a bare array — the runtime's delivery executor renders the pydantic envelope when it can hydrate the concept's class and falls back to the transport dump, a plain list, when it cannot. Measured live in both modes and both cases. `wireListOutput(results, elementSchema)` (`src/lib/wireOutput.ts`) unwraps a top-level `{ items }` when it sees one, leaves anything else for the schema to reject, and normalizes the items under `z.array(elementSchema)`; a plural narrower is now typed `<Code>[]` and parses that array, declaring no envelope. `<JsonResult>` reads its images off the array accordingly. Reported upstream to pipelex; the helper expires the day the runtime renders a list one way on every path.

- **A second source kind: `methods/<name>/method.json`, a manifest naming a method that lives elsewhere.** A method directory holds either `.mthds` bundles or exactly one selector — `method_ref` (a published package address) or `method_id` (a method in the key's org catalog) — never both. Putting the selector in `methods/` rather than in `sources.json` is what let every codegen rule survive unchanged: `sources.json` hashes the manifest the way it hashes a bundle, so bumping a published method's version is a one-line edit that `make check` then requires a regeneration for; orphan detection is untouched; and `npm run codegen` regenerates both kinds in one pass rather than growing a second path. The keyed scripts also learned the handshake a server-resolved selector needs — one `GET /v1/version`, refusing with the base URL and the missing capability named instead of surfacing a bare `403` — and print a selector-resolution 404's server message verbatim, since for a bad address it lists the packages the repository does contain.

- **A fifth example — "Text stats" (`methods/text-stats/`) — written entirely by `make add-method`.** It is the output of that command against `github.com/Pipelex/methods/text_stats@v0.1.1`, committed untouched, and it earns its place for a reason beyond demonstration: the scaffold's emitted files are strings inside a script, invisible to `tsc` until materialized, so the shipped slice is what compiles, lints and tests them on every `make all`. It is a `method_ref` rather than a catalog id deliberately — an id is scoped to one organization, so ours would 404 for every consumer.

- **`src/components/JsonResult.tsx` — the generic result view.** The typed output rendered as formatted JSON, plus an `<img>` for any web-renderable image URL it carries (`public_url ?? url`, one level down, the same preference `parseGeneratedImage` applies, and deliberately not `pipelex-storage://`). Every scaffolded form renders it, because a result component is a design decision about a specific shape and the scaffold has no design — it would be inventing headings for fields it has never seen.

- **`src/hooks/useFileInputs.ts` — the file seam, extracted from `PdfForm`.** Drop, size early-exit, encode through `fileToDataUrl`, write the `FileValue` back at the field's dotted path, and hold the id in the set the kernel reads as `uploadingIds` meanwhile. `PdfForm` adopts it with its own test passing unchanged, which is what says the behaviour did not move; a scaffolded form with a file input composes it rather than restating it.

- **The input forms are rendered from each method's own contract.** The template adopts [`@pipelex/mthds-form`](https://www.npmjs.com/package/@pipelex/mthds-form): `npm run codegen` now also asks `POST /v1/validate` for a method's pipe IO contracts and commits them as `src/generated/<method>/contracts.ts`, and the three demo forms derive every field, label, control and required-ness from that artifact. Add an input to a `.mthds` bundle, re-run codegen, and it appears in the form with no component edit. `src/components/RunInputsForm.tsx` is the single kernel composition — it decides foldability once, at mount, rather than from the live value, so clearing a seeded optional field cannot make its own control vanish mid-edit — `src/hooks/useRunInputs.ts` owns form values and readiness (the companion to `useRun`, which owns the run), and `docs/input-form.md` is the reference.
- **`src/lib/runInputs.ts` — the server-side input gate, sharing the kernel's rules with the browser.** Every Server Action opens with the kernel's own `gateRunInputs` over the same committed contract the browser rendered the form from; the module is a thin shim that renders the kernel's structured refusal as this template's `bad_request` error, plus `requireContract`, which throws when a contract lookup misses, since an undefined contract otherwise renders as an empty form with a live Run button. The browser runs `computeReadiness` for the Run button; the Server Action is the trust boundary, because a Server Action is a public endpoint, and the kernel keeps the gate a strict superset of what the button enforces — validating shapes, re-applying readiness's own emptiness rule (ajv's `required` only asserts key presence, so an empty string would otherwise pass), and building the `{concept, content}` payload, in one call rather than a host-side assembly of its lower-level steps. The two sides are held to agreement by a test that runs both over one table of inputs, rather than by a comment asserting they match.
- **A fourth example — "Complex inputs" (`methods/complex-form/`) — whose method declares more than a text box.** It takes the required text, an optional structured input (a concept with an enum child and a free-text one) and a plural text input, so the form derives a nested card with its own optional-folding, a segmented enum, and a repeater with add/remove. The example exists for what its code does _not_ contain: `src/components/ComplexForm.tsx` is no longer than `EntityForm.tsx` and names no input, no label and no control. It is also the first committed method to reach the structured and plural branches of the shared gate, so its form states join the readiness-versus-gate table in `src/lib/runInputs.test.ts` — which is the check that catches an input shape the browser accepts and the run then rejects.

  **Two input shapes were avoided while they were upstream kernel bugs, and both are fixed by `@pipelex/mthds-form` 0.3.0**: a `native.Number` input rendered but could never run, because its value was not wrapped into the `NumberContent` envelope its own contract declares; and a **required** field inside an **optional** structured input was rejected on a form nobody opened, because the kernel materialized an empty shell that ajv then judged. Every field of `ExtractionFocus` is still optional, but as a design choice rather than a workaround.

- **A drift gate for artifacts the codegen lock cannot sign.** `contracts.ts` carries no codegen stamp on purpose — the SDK's orphan rule deletes stamped files the lock does not track — so its SHA-256 rides in `sources.json`'s new `derived` map, written by the generator from the content it wrote and compared by `npm run codegen:check`. `npm run codegen:verify` re-fetches `/v1/validate` and compares the rendered bytes, since a crate fingerprint says nothing about another route's response.

### Changed

- **Tailwind 4, because the form kernel it already installs is written in Tailwind 4.** `@pipelex/mthds-form` 0.8.0 states its controls in v4's vocabulary — `outline-hidden`, `aria-invalid:`, `data-placeholder:`, `wrap-break-word`, `field-sizing-content`, the `(--radix-…)` variable form — and this template was compiling those class names with a v3 build, which turns each of them into **nothing**: the controls kept their layout and silently lost their focus ring, their invalid state and their placeholder colour. Measured before and after on the built stylesheet, the `@source` directive now contributes classes the v3 build emitted none of, and the production bundle carries `field-sizing:content`, `overflow-wrap:break-word`, both `--radix-select-*` sizing variables and `outline-hidden` with the `@media (forced-colors: active)` block that is the whole reason that utility exists.

  `tailwind.config.ts` is retired: v4 is configured in CSS, so the `content` globs, the shadcn token mirror, the radius scale and the animation plugin all move into the top of `src/app/globals.css` as `@source`, `@theme inline`, and an `@import "tw-animate-css"` in place of the `tailwindcss-animate` plugin. `postcss.config.js` becomes the single `@tailwindcss/postcss` plugin, and `autoprefixer` goes — v4 prefixes on its own.

  Two details in that stylesheet are load-bearing and are commented as such. The `@source` line must sit **after** the whole run of `@import`s, or the bundler drops the imports that follow with a warning rather than an error and the sheet arrives with no tokens. And the `@theme inline` mapping is a bare `var(--border)`, never the `hsl(var(--border))` of the v3 arrangement: kernel 0.8.0 changed each token from an HSL triplet to a whole colour, so the old wrapper now produces `hsl(hsl(…))` — not a colour, discarded by the browser, the element left transparent, nothing logged. **That half was already broken here**, because 0.8.0 was installed without the move: the v3 build emitted every one of the controls' semantic colour declarations in the double-wrapped form, so the controls' borders, surfaces and text colours were resolving to nothing at all. They now measure as the tokens intend — a resting border of `--border`, a `--destructive` red under `aria-invalid`, a `--primary` border and a 1px `--primary/40` ring on `:focus-visible`, and a placeholder at 70% of `--muted-foreground` — on every one of the five example tabs.

  The app's own chrome is unchanged in appearance. Two utilities were renamed where v4 renamed them, both verified to emit the same declaration as before rather than merely to compile: the bare `rounded` became `rounded-sm` (v3's `0.25rem`, and `calc(var(--radius) - 4px)` under the token mapping, are the same 4px), and `shadow-sm` became `shadow-xs` (byte-identical rule). Every border in this repo names its own colour, so v4's change of the default border colour reaches nothing, and there is no bare `ring` for its width change to reach. What is genuinely new is a base-layer rule restoring `cursor: pointer` on enabled buttons, which v4's preflight drops and the kernel's controls rely on.

- **`src/components/ExampleTabs.tsx` is data-driven, with two insertion anchors.** `TABS` carries each example's component, and the panels are mapped from it rather than written out one `<div role="tabpanel">` per form — a small simplification on its own, and what makes a scaffolded tab one insertion point instead of two. Two marker comments (`// add-method:imports`, `// add-method:tabs`) are where `make add-method` inserts; the match is on the token alone, so the prose after a marker can be reworded, but the tokens themselves must not move, and a test reads the real file so that a template edit which loses one fails the suite rather than the next person's scaffold run.
- **`blockingRun` and `durableRun` take the SDK's `PipelexStartOptions`, not the pure-protocol `StartOptions`.** The run selectors `method_ref` and `method_id` live on the Pipelex run extensions, which the wider type intersects in — so the widening is what makes an action that names a method by selector possible at all. Every extension is optional, so the four hand-written actions satisfy it unchanged.
- **Breaking: every committed tree was regenerated on engine `0.56.0`, and `contracts.ts` gained `json_schema` on each pipe output contract.** The `mthds` protocol types now require it, so every previously committed `contracts.ts` failed to typecheck against the current dependency floor. Every crate fingerprint is unchanged — the regeneration is a restamp plus that one field. It also brought the ts-zod emitter's `.nullish()` projection of non-required fields live, which is `dropWireNulls`'s documented expiry condition; the helper is **kept** for now, because an older engine still emits `.optional()` for anyone regenerating against one, and its tests build that shape by hand instead of relying on a committed schema.
- **`npm run codegen` and `npm run codegen:verify` currently need `PIPELEX_BASE_URL=https://api-dev.pipelex.com`.** Measured 2026-09-05: `api.pipelex.com` is on an older release that returns no `input_form` view from `/v1/validate` — which codegen needs for every method, bundle-sourced ones included — and advertises no `method_ref`. This replaces the v0.4.0-era claim that regeneration runs against the default hosted URL with nothing but a key. It reaches no one who only runs the app: `codegen:check` is pure hashing, so `git clone && make all` still passes with no key and no network.
- **Breaking: the input forms render from the method's wire input-form descriptor, committed by codegen.** `npm run codegen` now opts into `/v1/validate`'s structured view with `views: ["input_form"]` and writes the returned descriptor into each `src/generated/<method>/contracts.ts` as a second export, `INPUT_FORM`, beside `PIPE_IO_CONTRACTS` — the seam the codegen design note always reserved for exactly this, landed as one artifact at one call site. The kernel's `fieldsForContract(contract, descriptor)` maps that descriptor structurally instead of guessing kinds from concept names and schema shapes, so `useRunInputs` takes it as a second argument (`useRunInputs(CONTRACT, DESCRIPTOR, seed?)`) and each form adds one module-level lookup through the new `requireInputForm` (`src/lib/runInputs.ts`, `requireContract`'s twin — loud on a miss, because a missing descriptor renders as an empty form with a live Run button). The Server Actions are untouched: the run gate deliberately validates against the contract alone. Two mechanical notes: `INPUT_FORM` is emitted with an `as` assertion rather than a `:` annotation for now — the deployed hosted engine still puts a `name` on a list's `item`, which the standard's closed shape forbids and tsc would reject; fixed upstream in pipelex 0.54.0, and the emitter reverts to an annotation once the hosted engine carries it — and the regeneration also restamped every tree for the engine move `0.52.0 → 0.53.0`, a no-semantic-change rewrite the crate fingerprints confirm.
- **Bumped `@pipelex/mthds-form` to `0.5.0`** (was `0.4.0`) — the derivation swap this template's descriptor adoption above rides on. Beyond the new derivation, two changes reach a consumer of this template: a control's DOM id is now derived from its field path behind a `useId` prefix so two forms on one page cannot collide — which also means an id is no longer predictable from the input name, and the one test that reached `#must_include.0` now queries by role (`FieldDomIdProvider` is the kernel's escape hatch for hosts that need predictable ids) — and `native.Date` / `native.Html` inputs now travel as their declared content models, which no method in this template declares. The run gate keeps its signature and walks the contract's schema for itself.
- **Bumped `@pipelex/sdk` to `0.15.0`** (was `0.14.0`). The validate report now types its standard artifacts by importing them — `pipe_io_contracts` and `input_form` are `PipeIOContracts` and `InputForm` from `mthds/protocol`, re-exported through the SDK barrel — so the codegen scripts drop their `Record<string, unknown>` handling and pass typed payloads straight to the renderer. The wire is unchanged; the `mthds` floor moves to `^0.24.0`, which is where the descriptor's discriminated-union types live.
- **The local dev and Playwright port moved from `4100` to `4300`.** Port 4100 is taken by the `pipelex-server` local stack, which publishes its sandbox container — the MTHDS build chatbot — on `127.0.0.1:4100`; the starter was the side free to move, since `pipelex-app` hardcodes that port to reach the chatbot. The clash was silent in the worst way: Docker holds IPv4 loopback, so `next dev` still bound 4100 on IPv6 and reported `Ready`, while Playwright's health check resolved to IPv4 and read the container's 404 until it gave up with `Timed out waiting 120000ms from config.webServer`. The port is now declared once in `playwright.config.ts` and derived into both `baseURL` and `webServer.url`, alongside the `-p` flags in `package.json`.
- **Bumped `@pipelex/mthds-form` to `0.3.0`** (was `0.2.0`). Two behavior changes reach a consumer of this template: an untouched optional structured input now stays absent from the wire instead of traveling as a shell the gate then judges, and a blocked run's validation error names the field identifier the method declares (`audience`) rather than the generated title (`Audience`). One edge of the old bug family survived that release — a **required** structured input with no required children was rejected by the gate while readiness left the Run button live — and is closed by the `0.4.0` bump that follows: such an input now gates on both sides until it is touched, and the test that pinned the divergence now pins the agreement.
- **Bumped `@pipelex/mthds-form` to `0.4.0`** (was `0.3.0`), adopting its fix campaign end to end. The contracts are regenerated to the reshaped wire an input contract now mirrors verbatim — `presence` / `multiplicity` / `item_count` in place of a boolean `optional` — and the server-side gate is the kernel's own `gateRunInputs` (see the reworked `src/lib/runInputs.ts` bullet above). Three behaviour changes reach a consumer of this template, none of them bugs: a **required structured input** must be touched before Run lights up, because untouched it would be refused by the gate and the button now agrees; a **touched optional input** joins the readiness count and is held to what its concept declares, so the count reads 3 of 3 while it is untouched, 3 of 4 once it is started, 4 of 4 once it is done; and a **whitespace-only string** counts as unfilled on both sides, which closes the known gap this changelog used to carry. The kernel also stops shipping its run-gate validator to the browser — ajv is measurably absent from this template's client chunks.
- **Bumped `@pipelex/sdk` to `0.14.0`** (was `0.13.0`). No code change: this template calls `validateFiles` with named options (unaffected by `validate()`'s new positional `views` argument), reads validation error items with `??` (unaffected by their optional members widening to `T | null`), and never passed `method_id` through `extra`. The release's additions — validation `warnings`, structured `views`, `suggested_fix` repair proposals, `method_id` as a typed run option, `deleteMethod` — are available but unused here.
- **Breaking: the Server Actions take the method's schema-shaped input dict.** `runExtractEntitiesBlocking("some text")` becomes `runExtractEntitiesBlocking({ text: { text: "some text" } })`, and the PDF trio takes `{ document: { url, filename } }` instead of `{ dataUrl, filename }`. Inputs consequently travel to the API in the runtime's explicit `{concept, content}` envelope. Verified live in both execution modes, and against `prepareInputs`, which accepts the envelope as readily as a bare value and preserves it on output.
- **Breaking: the hand-written per-input guards are deleted, not kept as belt-and-braces.** The empty-text checks in each action and the client-side file type check in the PDF form are gone; the kernel gate and the server's MIME check replace them. Two survivors are deliberate and documented: the client-side size check stays as an early exit on the same exported constant (past the cap the payload cannot fit the Server Action body limit), and the empty-MIME re-wrap stays because it is an encoding fix for browsers that report no `file.type` for a valid PDF, not a validation.
- **The PDF example uses the kernel's dropzone**, including its "paste a URL instead" affordance — so a document input can now be an `https://` or `pipelex-storage://` reference with no upload at all. The old staleness token for a second file picked mid-encode is gone: while a file is arriving the kernel shuts every door into that value — the dropzone, and since `0.4.0` the "paste a URL instead" toggle and the URL input behind it — so the form passes plain run state as `disabled` rather than a form-wide resolving flag. The one write path that guarantee cannot cover is the host's own chrome: the sample-PDF shortcut writes into the same field, so it disables itself while the field resolves.
- **A pasted storage URL can be previewed.** The kernel previews a file it took through its own dropzone from an object URL it made; for any other value it asks the host to resolve `value.url` and spins until that answers. A `pipelex-storage://…/x.pdf` pasted through the control's own "paste a URL instead" reaches that path, so with no resolver its Preview spun forever. `PdfForm` now supplies one that hands the URI straight back, letting the kernel's "Preview unavailable" fallback render. Since `0.4.0` that resolver is consulted for `pipelex-storage://` values alone — the kernel paints `http(s):`, `data:` and `blob:` URLs directly — and the two preview gaps this bullet used to report as upstream (a replaced file previewing as the earlier one, the sample PDF having no preview at all) are fixed in that release.
- **The file gate checks the scheme before the bytes, against a closed set, and finds the files by walking the method's wire descriptor.** `checkFileInputs` (`src/lib/fileEncoding.ts`, replacing the action-local `checkDocumentBytes`) accepts `data:`, `https://` and `pipelex-storage://` and refuses everything else. The SDK's `prepareInputs` resolves any string it does not recognise as a **local filesystem path** — it reads that path and uploads it — so a gate that treats "not a data URL" as "nothing to check" turns a public Server Action into an arbitrary server-side file read whose contents come back summarized to the caller. Where the files _are_ is read off the pipe's `PipeInputFormDescriptor` (the action looks it up with `requireInputForm`, beside `requireContract`), descended exactly as `prepareInputs` descends it — `document` / `image` is a file position at any depth, `object` walks its declared fields, `list` walks each item — so the set of positions the gate verifies is by construction the set the SDK goes on to upload. That is what lets a method take `cvs: Document[]`, or a file nested in a structured concept, without a value heuristic on either side: a text field merely named `url` is not a file, a `Document` two levels down is, and a bundle rename moves the gate with the descriptor rather than silently lapsing it. A present file position that holds neither a source string nor `{url}` content is refused, so the verdict rests on this walk rather than on the shape gate in front of it; the SDK's compact form — a bare source string where `{url}` would go — is read like the object form, because `prepareInputs` resolves the two identically. `make add-method` scaffolds the same file path for a file at any depth (the gate, `prepareInputs`, the `useFileInputs` seam), and lists the positions on a `files:` line of its plan instead of warning that a nested one is out of reach.
- **Tailwind gains the form kernel's token contract.** `tailwind.config.ts` adds the package bundle to `content` (its classes ship compiled, outside every source glob), mirrors the shadcn colour and radius tokens, and adds `tailwindcss-animate`; `@pipelex/mthds-form/theme.css` supplies stock token values, imported before `globals.css` so a host override wins. Restyling the forms is now a matter of overriding CSS variables.
- **`make use-local` / `make use-npm` now cover `@pipelex/mthds-form` alongside `@pipelex/sdk`.** `use-local` packs and installs the sibling `../mthds-form` in the same single `npm install` as the SDK tarball (one call on purpose — a second `--no-save` install re-reconciles against the lockfile and can silently revert the first tarball), and `use-npm` restores both packages at `@latest`, re-pinning `package.json` for each.
- **`POST /v1/codegen` is served on `api.pipelex.com`**, so the v0.4.0 caveat that pointed `PIPELEX_BASE_URL` at the dev origin _for the codegen route_ is gone from the README, the environment table, `.env.example`, `AGENTS.md`, the docs, and the codegen script's own error message. Regeneration as a whole still wants the dev origin for now, for a different reason and on a different route — see the `input_form` / `method_ref` bullet above.

### Fixed

- **The `bump-mthds-form` skill no longer names functions that do not exist.** Its "gate and readiness" seam list still described the hand-rolled gate this template had before it adopted the kernel's own `gateRunInputs` — `buildRunInputsSchema`, `prepareRunInputs`, `validateRunInputs`, `mustBeFilled`, `fieldFilled`, none of which any file imports, and `fieldsForContract` attributed to the wrong module — so the next bump would have read the kernel's changelog against a surface this repo has not consumed for several releases. Both seam bullets are rewritten from the actual imports, and the wire-descriptor half (`getPipeInputForm`, `requireInputForm`, `PipeInputFormDescriptor`) that landed after the skill was written is now named at all. Three things it did not say before and now does: `gateRunInputs` must stay one call rather than be re-assembled from the kernel's lower-level steps; `ValidationMessageKey` breaking `make typecheck` is the seam working, and the fix is to add the missing English wording; and `@pipelex/mthds-form` and `@pipelex/sdk` share their protocol types through one deduped `mthds` install, so a kernel release that moves to an `mthds` minor the installed SDK's range does not cover splits those types into two identically-named, incompatible ones — `npm ls mthds` diagnoses it, and the cure is bumping the SDK in the same commit.

- **The example tab row pushed the page sideways on a phone.** The tablist is a flex row whose buttons shrink to their longest word, so it has a wrap floor rather than a fixed width — which is why three tabs were survivable and the fourth was not. Measured in Chromium against the running app, the fourth tab moved the horizontal-scroll threshold from 284px to 370px, so a 320px iPhone SE gained 51px of sideways page scroll and the very common 360px Android class gained 11px, with the last tab off-screen; 375px and wider were unaffected either way. Nothing sets `overflow-x-hidden` on `html`, `body` or `main` and the layout declares no viewport override, so the excess propagated to the viewport rather than being clipped. The row now wraps (`flex-wrap`), which is a floor rather than a new threshold: a flex item is placed at its hypothetical width and only shrinks when it alone exceeds the line, and the widest tab is far narrower than the content box at any realistic width. Scrolling the row instead was rejected — it needs custom scrollbar suppression, which Tailwind 3 has no utility for.

- **A PDF between roughly 3.2 MB and the advertised 8 MB cap crashed the Server Action instead of running.** `validateDataUrl`'s base64 shape check was a repeated-group regex, and V8 walks one with a recursive backtracking stack: past about 4.47 M payload characters it threw `RangeError: Maximum call stack size exceeded` rather than returning a verdict, surfacing as an opaque transport failure. That also made `file_too_large` unreachable, since anything large enough to trip it blew the stack first. The check is now a flat alternation plus an explicit length rule — the same predicate, linear — and size is tested before shape. Pre-existing, not introduced by the form adoption.

- **A rejected file left its error on screen after the input was fixed.** "File too large" is set by the drop handler, but the kernel's "paste a URL instead" writes straight through `onValuesChange` without touching it — so the alert outlived the value that caused it. The setter now clears the error, which is where a rejection tied to a value belongs.

- **An optional input the user filled disappeared when the section was collapsed.** Foldability is decided at mount, deliberately, so that clearing a seeded field cannot unmount the control mid-edit. But the decision was never revisited, so a field filled while the section was open still counted as foldable: collapsing hid it, the toggle went on describing it as one of the empty inputs it was offering to reveal, and its value went out on the run anyway. The set is now re-decided on the way back to collapsed — the one moment where nothing is being edited, so the protection the freeze exists for is not weakened.

- **`npm run codegen` could write a permanently broken tree and exit 0.** Two ways, both silent. If the server ever returns an artifact named `contracts.ts`, the locally emitted one overwrote it, and `codegen:check` then reported `hand-edited` forever with a remedy that reproduced the same tree — refused up front now, like a changed `lock_filename`. And if the SDK's orphan rule ever stopped exempting unstamped files, the orphan pass would delete `contracts.ts` while the sidecar still recorded its hash — the writer now fails loudly instead, which is what the ordering was always supposed to buy.

## [v0.4.0] - 2026-08-21

### Added

- **Type generation from the `.mthds` bundles.** `npm run codegen` (`make codegen`) sends every method under `methods/` to the API's `/v1/codegen` route and writes what comes back, byte-for-byte, to `src/generated/<method>/`: zod schemas with their inferred TypeScript types, binders over those schemas, and a `codegen.lock`. The trees are committed, so `git clone && make all` passes without an API key. This replaces the hand-written output shapes the template used to keep in `src/types/`, so the types can no longer drift from the bundles that declare them. One caveat while it lasts: `/v1/codegen` is served by `api-dev.pipelex.com` and `api.pipelex.com` still answers `403` pending its deploy, so regeneration needs `PIPELEX_BASE_URL` pointed at api-dev today.
- **Two staleness gates over the generated trees.** `npm run codegen:check` (`make codegen-check`) is offline and needs no key: it verifies each tree against its own lock and compares a `sources.json` sidecar of source hashes against the `.mthds` files on disk, so editing a bundle without regenerating fails the build instead of shipping types that quietly lie. It is wired into `make check`. `npm run codegen:verify` (`make codegen-verify`) asks the question the offline check cannot — whether the committed tree still comes from the crate the method resolves to today — by comparing live `crate_fingerprint`s against the locks. It needs a key, writes nothing, and stays out of `make all`.
- **Security guards on the codegen scripts.** A plaintext `http:` guard refuses a non-loopback `PIPELEX_BASE_URL`, since the scripts send the API key as a bearer token and write server-supplied TypeScript into the repo. A containment guard checks every path the response names before anything is written, refusing the method whole if one resolves outside its tree.
- **`import "server-only"` in `src/lib/wireOutput.ts`**, so calling a generated narrower from a `"use client"` component fails the Next build instead of silently shipping zod plus every generated schema to the browser.
- **`tsconfig.scripts.json`**, which type-checks `scripts/` under `make typecheck` the way `tsconfig.e2e.json` covers the Playwright specs. The scripts are native-Node TypeScript, so the template gains no `tsx` or `ts-node` dependency.
- **A `docs/` directory, `AGENTS.md`, and a removal checklist.** `docs/codegen.md` is the design reference for the generated-types workflow and `docs/adopt-in-an-existing-project.md` is an executable checklist for transplanting the pattern into an existing app. `AGENTS.md` gives agents other than Claude Code the rules that matter. The README's new "Remove an example" section lists the full vertical slice a demo owns, so stripping one doesn't have to be assembled from compile errors.

### Changed

- **Breaking: output field names are wire-native snake_case.** `DocumentSummary` is now `{ title, doc_type, key_points }` and the image envelope carries `public_url`, `mime_type`, and `source_prompt`. The names travel unchanged from the bundle to the components, because a hand-maintained camelCase mirror is exactly the duplication this release removes.
- **Breaking: `src/lib/runOutput.ts` is gone**, replaced by `src/lib/wireOutput.ts`. The narrowers in `src/types/` are now thin adapters over the generated binders rather than hand-written shape-checkers; `findOutputContent`'s predicate search is subsumed by the generated schema's own `parse`, which rejects arrays, primitives, and `null` with a message naming the failing field.
- **A schema-guided wire-null normalization step, and it is a workaround with an expiry.** The projection emits a non-required concept field as `.optional()`, which in zod rejects `null`, while the runtime serializes an unset optional field as an explicit `null` — verified against a live image run. `dropWireNulls(value, schema)` strips a null-valued key only where the schema says a `null` there means absence, leaving a `null` inside a `z.record()`, a `.nullable()` field or a `.default()` field exactly as the pipeline sent it. It is deletable once the emitter emits `.nullish()`, and is reported upstream.
- **Bumped `@pipelex/sdk` to `^0.13.0`** (the declared range was `^0.5.1`) and added `zod` as a runtime dependency, since the generated binders validate run output inside Server Actions at request time. No migration was needed here: the intervening breaking changes are on the methods-catalog surface this template never calls, while `0.12.0` and `0.13.0` added the crate routes and the offline drift check the new scripts are built on.
- **`src/generated/` is excluded from Prettier and ESLint, deliberately.** The emitter targets Prettier's defaults while this repo prints at 100 columns, so formatting those files would rewrite their bytes and break every stamp. TypeScript still covers them in full.
- **The codegen scripts are thin CLI entries over a tested `scripts/lib/`.** All three ran their logic at module top level, so importing one executed a whole run and the orchestration could not be tested — including `writeTree`, the only code in the template that deletes files. Each module now owns its whole contract, exit code included.
- **The template assumes the hosted Pipelex API throughout — docs, error copy, comments, and specs.** Self-hosting is no longer offered as a supported path, and the localhost special case is gone: when a request doesn't reach a working Pipelex API, the error now says what the configured URL fails to provide and steers to verifying `PIPELEX_BASE_URL`.
- **The shared-helper tests no longer import any example's adapter.** `blockingRun.test.ts` and `durableRun.test.ts` now use inline fixture narrowers, so removing a demo example never touches the shared layer's tests.

### Fixed

- **Breaking: `parseGeneratedImage` gates a `data:` URL's media type against an allow-list, not just its scheme.** The validated URL feeds `<ImageResult>`'s download link as well as its `<img>`, so a saved payload runs on a `file://` origin once opened — which left `data:image/svg+xml` open as an active-content sink under a media type that passes for an image. Only `image/png`, `image/jpeg`, and `image/webp` are accepted, with a message of its own for a refused SVG. `http:` and `https:` outputs are unchanged, which is every image this template actually receives.
- **The codegen gate could be silently wrong in several ways, each now producing a loud, correct verdict.** Symlinks and special files were invisible to the walk and are now refused by name; lossy UTF-8 decoding let a corrupted artifact hash to its locked value and is now fatal; an empty `methods/` exited before orphan detection ever ran; a tree differing from its method's name in case only now gets a rename remedy rather than a delete one; and a stray `.DS_Store` no longer fails the check with a remedy naming a directory that does not exist.
- **`npm run codegen` deleted hand-written files parked in a generated tree.** Cleanup decided what it could remove with a filename test while the SDK's orphan rule also requires a codegen stamp, so a sibling module the generated header invites consumers to write was reported healthy by the check and destroyed by the next regeneration. Cleanup now defers to the SDK's own verdict, so the two agree by construction.
- **`codegen:check` reported every method stale on a Windows checkout.** Source hashes were taken over raw bytes, so a CRLF checkout disagreed with every committed hash. `hashSource` now normalizes line endings before hashing, the same normalization the SDK already applies to artifacts and locks. Nothing changes on an LF checkout.
- **A renamed lock file could have left the offline check validating the obsolete one.** The writer took whatever `lock_filename` the response named while the check has always opened `codegen.lock`; it now refuses any other name and writes nothing for that method.
- **`dropWireNulls` is depth-capped**, so a self-referential concept can no longer overflow the stack inside a Server Action. Past the cap the value passes through untouched and the generated schema still owns the verdict.
- **An empty-string `public_url` failed an image run that had a perfectly good `url`.** `public_url ?? url` let `""` win over the real URL; both that and `<ImageResult>`'s `alt` text now use `||`.
- **`make use-npm` restored a stale version instead of the current one.** It ran `npm install @pipelex/sdk`, which re-resolves the range already declared rather than fetching the current release — a silent downgrade, since a caret range never crosses a minor pre-1.0. It now installs `@pipelex/sdk@latest` and echoes the version it restored.
- **The README's "File & image inputs" section documented code deleted in v0.3.0.** It now matches the actual flow: validate the data URL server-side, hand it to `client.prepareInputs()`, and run against the `pipelex-storage://` reference it returns.

### Removed

- **Internal planning notes (`wip/`) are untracked again**, as v0.1.1 already decided before open-sourcing. The codegen design rationale they held now lives in `docs/codegen.md`.

### Security

- **Bumped `next` to `^16.3.1`** (was `^16.2.9`), clearing every high-severity advisory `npm audit --omit=dev` reported against this template's production tree. All of them came in through Next.js — Server Action denial of service, SSRF via rewrites and on custom servers, cache confusion, Image Optimization denial of service, disclosure of internal Server Function endpoints, a Turbopack middleware bypass — plus its pinned transitives `postcss`, `nanoid`, and `sharp`. `eslint-config-next` was raised alongside it to keep the linter in lockstep.
- **Bumped the `postcss` dev dependency to `^8.5.23`**, resolving arbitrary `.map` file disclosure and XSS through unescaped `</style>` in stringify output, so the full `npm audit` is clean with development dependencies included.

## [v0.2.0] - 2026-07-05

### Changed

- Breaking: swapped the Pipelex SDK from `mthds` (`MthdsApiClient`) to `@pipelex/sdk` (`PipelexApiClient`). `PipelexApiClient` reads `PIPELEX_API_KEY` / `PIPELEX_BASE_URL` natively, so the client is constructed bare with no env-var bridging. Error classes are imported from the `@pipelex/sdk` barrel (it has no `/errors` subpath; the barrel is client-bundle-safe).
- Breaking: renamed the env var `PIPELEX_API_URL` to `PIPELEX_BASE_URL` for consistency with the SDK's `baseUrl` naming. There is no read alias — update `.env.local` / your environment.
- `make use-local` / `make use-npm` now target the sibling `../pipelex-sdk-js` repo instead of `../mthds-js`.
- Bumped `@pipelex/sdk` to `0.2.0` (was `0.1.5`). No code changes needed for the `0.2.0` breaking renames (constructor option `apiToken` → `apiKey`, env var `PIPELEX_API_URL` → `PIPELEX_BASE_URL`): this repo constructs `PipelexApiClient` bare and already used `PIPELEX_BASE_URL`.
- Bumped `@pipelex/sdk` to `0.2.1` (was `0.2.0`), which makes the ESM-only SDK loadable from CommonJS (`default` export condition). The e2e specs now import `DEFAULT_API_BASE_URL` from the SDK directly instead of mirroring it as a local constant in `e2e/liveApi.ts`.
- Raised the minimum Node.js to 22.12 (`engines.node: ">=22.12.0"`, was `>=22`), matching the SDK's new floor: Playwright loads the e2e specs via CommonJS `require()`, and `require(esm)` is only unflagged from Node 22.12.
- Bumped `@pipelex/sdk` to `0.3.0` — one resolved output accessor across both execution modes. `RunResults.main_stuff` is now required (non-null), and the blocking `execute()` returns a `PipelexExecuteResult` whose `.main_stuff` the SDK resolves out of the working memory (via the response's `main_stuff_name`). `executeBlockingRun` therefore adapts the blocking response onto `RunResults` as `{ pipeline_run_id, main_stuff }`, and `findOutputContent` reads only `main_stuff` — the `pipe_output` working-memory search arm is gone, so both modes narrow the same resolved field.

### Fixed

- Blocking and durable modes now agree on which output is the "main" one. Previously the blocking path dropped the server's `main_stuff_name` and had `findOutputContent` guess the main output by predicate-shape-matching the first working-memory entry, so a pipeline with an intermediate stuff matching the same narrower predicate could render the wrong result in blocking mode while durable mode read the true `main_stuff` and was correct. With the SDK resolving `.main_stuff` on both paths, the shape-guessing is gone and the two modes can't disagree (closes the latent finding tracked in `wip/durable-runs-review-followups.md` #6).
