# TODOS — finish the turn to hosted-API-only

## The decision

This template is presented for use with the **hosted Pipelex API** exclusively — it is the only deployment that serves every endpoint the template needs (durable run lifecycle, file upload/storage, codegen). The README already states this, but the error layer, several code comments, the unit tests, and one e2e spec still carry copy written for a world where developers ran the open-source `pipelex-api` runner locally. That story is over, and we do not narrate it: nothing in this repo's developer-facing surfaces (error messages, hints, comments, docs, specs) may mention the OSS runner, self-hosting, or starting an API locally.

The replacement framing, everywhere: **when a request doesn't reach a working Pipelex API, the problem is the URL (or the network) — help the developer verify `PIPELEX_BASE_URL`.** Environment targeting stays fully supported: `PIPELEX_BASE_URL` is how we point at dev / staging / prod (`api-dev.pipelex.com`, `api-staging.pipelex.com`, `api.pipelex.com`), and that is a different concern from self-hosting. Nothing about env overrides changes.

## Principles for the rewrite

- **Diagnose forward, never backward.** An error may say what the configured URL _fails to provide_ ("doesn't serve the durable run lifecycle", "has no upload route") and steer to the fix ("check `PIPELEX_BASE_URL`", "the default is `https://api.pipelex.com`"). It may not name what the endpoint probably _is_ ("looks like a bare pipelex-api runner") — that's the old story leaking back in.
- **Error kinds and classification branches stay; copy changes.** The SDK error classes (`RunLifecycleUnavailableError`, `UnsupportedUploadCapabilityError`, the `StartRequiresAsyncOrchestration` error_type, …) are wire/SDK contracts and still classify real failures — a wrong URL can still 404 the lifecycle route. We keep every branch and its kind; only the messages, hints, and comments are rewritten.
- **No remedy may recommend an unsupported setup.** In particular, "switch to Blocking mode — it works against any runner" goes away as a remedy for `lifecycle_unavailable` / start-refused: if durable doesn't work, the URL is wrong, and the fix is the URL.
- **Tests are documentation in a template.** Fixture URLs and test names that read as "local runner" documentation get neutralized, not just kept passing.
